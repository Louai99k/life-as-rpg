## Narrative Voice

Rules docs should read clean, direct, and unambiguous. Flavor text may be dramatic, but mechanical language must stay plain and exact.

## Table Style

Tables should prioritize quick scan value. Each table needs clear label, roll source, and interpretation rule.

## Session Framing

Session notes and panel outputs should present information in consistent order so player does not search across tools or pages to understand current situation.

## Symbol System

Symbols may be used to mark state, fact, danger, or reminder. Symbol layer should support readability, not become another rules burden.

## State Markers

State markers show current category of status such as active, unstable, blocked, or resolved. Final symbol list should define exact meaning of each marker used.

## Fact Markers

Fact markers identify canon or non-optional system truths that cannot be ignored during play or design.

## Warning Markers

Warnings highlight high-risk rule interactions, dangerous outcomes, or design constraints that should not be overlooked.

## Important Note Markers

Important note markers call attention to practical reminders that matter for play but are not themselves full rules.

## Header Conventions

All docs should use stable heading structure, naming pattern, and numbering logic so cross-references remain easy to maintain.

## Log Format

Session logs should eventually define standard fields such as:

- date or session id
- mission
- encounter summary
- rewards
- state changes
- unresolved hooks

## Flavor Limits

Flavor should reinforce identity of system without obscuring mechanical meaning. If flavor sentence hides rule intent, rewrite rule first and move flavor second.

## Consistency Rules

Presentation chapter should define how terms, tags, ranks, symbols, and panel phrasing stay consistent across all docs and future tools.
